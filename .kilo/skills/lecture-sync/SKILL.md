# Навык: Синхронизация изменений между лекцией (.md) и слайдами (.pptx)

## Назначение

В каждом модуле курса в папке `Модуль N. <Название>/` лежат два связанных файла:

- `<N>_Лекция.md` — полный текст выступления;
- `<N>_Лекция.pptx` — слайды лекции.

Со временем они расходятся: правят текст лекции — нужно добавить/обновить слайды;
правят презентацию (иллюстрации, заметки) — нужно подтянуть изменения обратно в md.
**Этот навык вносит только дельту**, а не пересобирает колоду целиком.

> ⚠️ Это **не** `pptx-writer`. `pptx-writer` удаляет все слайды и собирает колоду
> заново — это затирает ручную работу (рисунки, диаграммы, отредактированные тела
> слайдов). `lecture-sync` меняет **только то, что изменилось**: вставляет новые
> слайды/блоки, обновляет изменившиеся заметки и заголовки, а нетронутое оставляет
> как есть. Полная пересборка (`pptx-writer`) — только когда нужна чистовая колода
> с нуля или когда расхождений слишком много.

## Два формата лекций

Навык сам определяет формат по содержимому `<N>_Лекция.md`:

| Формат | Где | Разметка слайдов в md | Ключ сопоставления |
|---|---|---|---|
| **Маркеры** | Модуль 1 (эталон) | `[Слайд N] …` / `[Слайды N–M]` | номер + порядок |
| **Подразделы** | Модули 2–8 | `### **N. <Заголовок>**` | номер `N` |

В обоих случаях текст выступления живёт в **заметках слайдов (notes)** pptx — туда
же его кладёт `pptx-writer` при генерации.

## Инструмент: `sync_lecture.py`

Скрипт: `.kilo/skills/lecture-sync/sync_lecture.py`.
Зависимости: `python-pptx` (`pip install python-pptx`). Python 3.8+.
Переиспользует оформление/парсеры из `generate_pptx.py`, поэтому вставленные слайды
получают тот же фирменный стиль (IBM Plex Sans, акцент #8E39E2, 16:9).

Запуск из корня репозитория (пути с пробелами/кириллицей — в кавычках):

```bash
# 1) ИЗУЧИТЬ расхождения (ничего не меняет):
python ".kilo/skills/lecture-sync/sync_lecture.py" report \
  "Модуль 2. Регрессия и градиентный спуск/2_Лекция.md" \
  "Модуль 2. Регрессия и градиентный спуск/2_Лекция.pptx"

# 2) ПРИМЕНИТЬ изменения в нужную сторону:
python ".kilo/skills/lecture-sync/sync_lecture.py" apply \
  "<N>_Лекция.md" "<N>_Лекция.pptx" \
  --direction md2pptx --mode add --dry-run
```

### Команды и флаги

| Команда / флаг | Что делает |
|---|---|
| `report <md> <pptx>` | Выводит отчёт о расхождениях (+ опц. `--json <file>` для сводки). |
| `apply <md> <pptx>` | Применяет изменения. |
| `--direction md2pptx` | Тянет изменения из **md → pptx** (по умолчанию). |
| `--direction pptx2md` | Тянет изменения из **pptx → md**. |
| `--mode add` | **Только добавить новое** (по умолчанию, безопасно): новые слайды/блоки и заполнение пустых notes. Существующее не перезаписывается. |
| `--mode update` | Дополнительно **перезаписывает** изменившиеся тексты/заголовки у совпавших слайдов. |
| `--mode all` | Дополнительно **удаляет** лишнее и пересортировывает слайды под порядок md. |
| `--dry-run` | Показать план (ПЛАН …), но **не записывать** файлы. |
| `--backup` | Сохранить `.bak` перед перезаписью. |

## Что делает скрипт, а что — агент

**Скрипт (автоматически):**
- Парсит md (оба формата) и pptx в общий список «слайдов» с номером, заголовком,
  текстом выступления и notes.
- Сопоставляет слайды md ↔ pptx: по номеру (формат 2) или по порядку (формат 1).
- **`md2pptx`**: вставляет новые слайды в правильные позиции, обновляет
  title/notes у изменившихся, может удалять лишние и пересортировывать (`all`).
  Нетронутые слайды (с ручной графикой) сохраняет.
- **`pptx2md`**: вставляет новые блоки (`[Слайд N]` или `### N.`) в нужные места md
  и обновляет текст у изменившихся.

**Агент (после применения):**
- Прогоняет `report` и **показывает пользователю**, что разошлось.
- Уточняет направление и режим через `question` (см. рабочий процесс).
- После `md2pptx`: перерабатывает тело **новых** слайдов в краткие тезисы
  (генератор кладёт туда только первую фразу-заглушку) — как в `pptx-writer`.
- Проверяет, что номера слайдов не «съехали» и порядок осмыслен.

## Рабочий процесс

1. **Определить целевой модуль** (номер/название/путь). Файлы —
   `<папка модуля>/<N>_Лекция.md` и `<N>_Лекция.pptx`.
2. **Проверить наличие обоих файлов.** Если `<N>_Лекция.pptx` нет — сначала
   сгенерировать его навыком `pptx-writer`. Если нет md — сначала `lecture-writer`.
3. **Убедиться в окружении:** `python` и `python-pptx` (`python -c "import pptx"`).
4. **Запустить `report`** и изучить сводку:
   - «Только в md» → изменения есть в тексте, но не в слайдах → перенос `md2pptx`.
   - «Только в pptx» → изменения есть в слайдах, но не в md → перенос `pptx2md`.
   - «Изменился текст/заголовки» → правки в уже совпавших слайдах.
5. **Уточнить у пользователя направление и режим**, если они не очевидны из запроса:
   - направление: `md2pptx` или `pptx2md`;
   - режим: `add` (только новое, безопасно) / `update` (перезаписать изменения) /
     `all` (ещё удалить лишнее и пересортировать).
6. **Сначала прогнать `apply --dry-run`** и показать «ПЛАН (…): добавлено …,
   обновлено …, удалено …». Если план устраивает — применить без `--dry-run`
   (с `--backup` для ценных файлов).
7. **После `md2pptx`** — переработать тела новых слайдов в тезисы (notes сохранять).
8. **Сообщить пользователю:** направление/режим, что добавлено/обновлено/удалено,
   путь к изменённому файлу; для `md2pptx` — какие новые слайды требуют ручной
   графики/тезисов.

## Примеры сценариев

- **«Я дописал раздел в лекцию (md)»** → `report`, видим «Только в md: слайд N» →
  `apply --direction md2pptx --mode add` → новый слайд появился в pptx, старые не тронуты.
- **«Я добавил слайд/иллюстрацию в PowerPoint»** → `report`, видим «Только в pptx» →
  `apply --direction pptx2md --mode add` → в md появился соответствующий блок с notes.
- **«Поправил формулировки в заметках слайдов»** (в md или в pptx) → `report` покажет
  «Изменился текст» → `apply --direction <нужная> --mode update`.
- **«Лекцию сильно перестроили, слайды рассинхронизированы»** → возможно, проще
  полный перегон через `pptx-writer`; `lecture-sync` — для точечных правок.

## Чего избегать

- **Не путать с `pptx-writer`.** Этот навык НЕ пересобирает колоду и НЕ трогает
  ручную графику/декор. Для чистовой сборки с нуля — `pptx-writer`.
- **Не применять вслепую.** Сначала `report`, затем `--dry-run`, затем запись.
  Большие расхождения (особенно в эталоне Модуля 1 — 93 слайда, заметки были
  расшифрованы вручную и расходятся с md) требуют внимания, а не авто-`all`.
- **Не использовать `--mode all` без `--dry-run`**: он удаляет «лишние» слайды и
  пересортировывает — на эталоне с расхождениями это опасно.
- **Не менять тему/мастер** новых слайдов — стиль берётся из шаблона через
  `generate_pptx`, чтобы колода оставалась единообразной.
- **Не рассчитывать, что номера слайдов идеальны.** При вставке «в середину»
  новый слайд получает свой номер и встаёт по порядку md; при необходимости
  перенумерацию делает агент.
- При правках **pptx → md** текст берётся из notes слайда; видимые тела слайдов
  (тезисы) в md не переносятся — лекция в md хранит именно текст выступления.

## Валидация

После применения убедиться, что:

1. Повторный `report` показывает **0 расхождений** по перенесённым изменениям
   (добавленное исчезло из «только в …», изменившееся — из «изменился текст»).
2. Файл открывается: `.pptx` — валиден, 16:9; `.md` — корректный UTF-8, структура
   (`### N.` / `[Слайд N]`) не сломана.
3. Для `md2pptx`: число слайдов выросло ровно на число добавленных; нетронутые
   слайды (с иллюстрациями) на месте и в прежнем виде.
4. Для `pptx2md`: md содержит новые блоки в правильных позициях; номера слайдов
   не дублируются и идут по порядку.
5. Пользователю сообщены направление, режим и список фактически добавленных /
   обновлённых / удалённых слайдов.
