# Навык: Написание полного текста теории модуля

## Назначение

В каждом модуле курса в папке `Модуль N. <Название>/` лежит файл `<N>_Теория.md`
(например `2_Теория.md`) — **полный конспект теории** модуля для самостоятельного
изучения студентами.

Это **глубокий и практический** материал: в отличие от обзорной вводной лекции
(`<N>_Лекция.md`), теория даёт определения, выводы, формулы и **исполняемый код**
на Python (pandas / scikit-learn / PyTorch и т.д.), привязанный к проекту модуля.
Это **не** слайды (`<N>_Лекция.pptx`) и **не** задание (`<N>_Задание.ipynb`) —
это связный учебный текст, по которому студент осваивает тему в течение модуля.

Эталон формы и стиля — `Модуль 1. Введение в ML/1_Теория.md`. Этот навык читает
целевой `<N>_План.md` и **создаёт** `<N>_Теория.md`, разворачивая раздел
`## Темы теории` (темы `Тема 0..N`) в полноценные главы-блоки `Блок 0..N`.

## Эталон

Перед написанием **обязательно** прочитать `Модуль 1. Введение в ML/1_Теория.md`
и воспроизвести его форму и стиль один-в-один (блоки, подразделы-абзацы, код,
формулы, списки). Берётся **форма**; содержание выводится из целевого плана и
собственных знаний по теме модуля. Не повторять тему Модуля 1 дословно —
переносить приёмы оформления.

## Источник содержания

Содержание выводится из целевого `<N>_План.md`:

- `## Темы теории` (`### Тема 0. <Название>` … `### Тема N. <Название>`) —
  **каркас** теории: каждая `Тема N` → глава `Блок N`; буллеты темы = обязательный
  список подвопросов, которые надо раскрыть в блоке.
- `### Умеют` (образовательные результаты) — **практические навыки**, которые
  теория обязана подкрепить кодом (обучить модель, реализовать алгоритм «с нуля»,
  закодировать признаки, подобрать гиперпараметры и т.п.).
- `### Знают` / `### Понимают` — понятия и принципы, которые надо объяснить.
- `## Проект (Kaggle)` — практическая задача модуля; примеры и код в теории
  по возможности привязываются к этому проекту (данные, целевая переменная,
  метрика соревнования).
- `## Материалы` — название статьи/ноутбука; **не выдумывать** ссылки на видео/
  статьи — если у эталона есть внешние ссылки (Яндекс.Диск, блоги), для нового
  модуля их оставлять нельзя без реального источника.

Если для модуля уже написан `<N>_Лекция.md` — прочитать его, чтобы
**согласовать терминологию** и **не дублировать** обзорный материал: лекция даёт
интуицию, теория уходит в детали, формулы и код.

## Структура теории (по эталону)

Файл строится из **блоков**, нумерация которых 1:1 соответствует темам плана
(`Тема N` → `Блок N`, сквозная от `Блок 0` до конца).

Общий каркас:

1. **Без frontmatter и без заголовка H1** — файл начинается сразу с `Блок 0. …`
   (как эталон). Никаких `#`, `---` в начале, оглавления или подвала в конце
   (теория, в отличие от лекции, **не имеет** вступительного абзаца, ЗАКЛЮЧЕНИЯ
   и подписи автора).
2. **`Блок N. <Название>`** — глава, по одной на каждую `Тема N` плана. Название
   берётся из `### Тема N. <Название>` (можно слегка раскрыть/уточнить).
   Количество блоков = количеству тем в `## Темы теории`.
3. Внутри блока:
   - **1–2 вводных абзаца** — что это за понятие/этап и зачем он нужен.
   - **Подразделы** — короткие заголовки обычным текстом на отдельной строке
     (например `Первичный осмотр данных`, `Стратегии обработки: когда и как
     заполнять?`). **Без** markdown-заголовков `###` и **без** нумерации.
     Каждый буллет `Тема N` плана раскрывается в 1+ подраздел.
   - В подразделах: определение, «почему это важно», формулы, **код на Python**,
     нумерованные/маркированные списки, английский термин в скобках, разбор
     примера из проекта модуля.
   - Блок завершается там, где тема исчерпана; переход к следующему `Блок N+1`.

Пример анатомии одного блока (по форме эталона):

```
Блок 2. Линейная регрессия и функции потерь

Линейная регрессия — простейшая модель обучения с учителем для непрерывной
целевой переменной. Она закладывает базу для понимания градиентного спуска
и регуляризации, которые разбираются далее.

Уравнение линейной регрессии
Модель предполагает линейную зависимость целевой переменной от признаков:

y_hat = w0 + w1*x1 + ... + wd*xd

В матричной форме предсказание записывается как y_hat = Xw, а аналитическое
решение (нормальное уравнение) даёт веса напрямую:

w = (X^T X)^{-1} X^T y

Функции потерь: MSE и MAE
1. MSE (Mean Squared Error)
   Штрафует большие ошибки квадратично, поэтому чувствительна к выбросам.
2. MAE (Mean Absolute Error)
   Линейный штраф, устойчива к выбросам, но недифференцируема в нуле.

Пример обучения (sklearn):

from sklearn.linear_model import LinearRegression

model = LinearRegression()
model.fit(X_train, y_train)
val_pred = model.predict(X_val)
```

## Стиль (строго по эталону `1_Теория.md`)

- **Язык:** русский.
- **Без markdown-заголовков `#`/`##`/`###`** — структура задаётся метками
  `Блок N. <Название>` и заголовками подразделов обычным текстом (как в эталоне).
- **Код на Python — обычным текстом, без ограждения ` ``` `** (как в эталоне):
  блок кода отделяется пустыми строками сверху и снизу, инструкции — пустыми
  строками друг от друга. **Inline** имена классов/функций/библиотек — в
  обратных апострофах: `StandardScaler`, `df.head()`, `nn.Module`, `fit_transform`.
- **Формулы — обычным текстом**, не LaTeX: `x_scaled = (x - mean_x) / stddev_x`,
  `accuracy = (число верных предсказаний) / (общее число пассажиров)`,
  `y_hat = Xw`, `w = (X^T X)^{-1} X^T y`.
- **Термины:** английский термин в скобках при первом упоминании
  (`разведочный анализ данных (Exploratory Data Analysis)`,
  `переобучение (overfitting)`, `утечка данных (data leakage)`).
- **Списки:** маркированные `-` и нумерованные `1.`/`2.`; вложенные пункты и
  продолжения — с отступом в 3 пробела. Нумерованные перечисления методов —
  с короткой «шапкой»-названием первой строкой и пояснением ниже
  (как способы кодирования и масштабирования в эталоне).
- **Тон:** учебно-объяснительный, с обоснованием «почему так» и практическими
  примерами (проект модуля, бытовые аналогии). Плотный, без воды.
- **Маркеры ✅ / ❌ / ⚠️:** допустимы точечно, как в эталоне, для хороших/плохих
  практик и предупреждений (например про data leakage). Других эмодзи **нет**.
- **Ссылки:** внешние URL (видео, статьи) — **только** реальные; не выдумывать
  ссылки на Яндекс.Диск/блоги для нового модуля.

## Рабочий процесс

1. **Определить целевой модуль** из запроса (номер, название или путь).
   Файл — `<папка модуля>/<N>_Теория.md`. Если модуль не указан однозначно —
   уточнить через `question`, предложив список `Модуль 2..8` (Модуль 1 уже есть).
2. **Прочитать эталон** `Модуль 1. Введение в ML/1_Теория.md` (форму/стиль).
3. **Прочитать целевой `<N>_План.md` целиком** (особенно `## Темы теории`,
   `### Умеют`, `## Проект (Kaggle)`).
4. **Если существует `<N>_Лекция.md`** — прочитать для согласования терминологии
   и чтобы не дублировать обзор (теория = глубже + код + формулы).
5. **Проверить, существует ли уже `<N>_Теория.md`.**
   - Если существует и в запросе не было явного «переписать» — уточнить у
     пользователя (дописать / переписать / отмена).
   - Для нового файла — писать с нуля.
6. **Извлечь исходные данные** из плана:
   - `### Тема 0..N` → каркас блоков `Блок 0..N` (названия) + обязательные
     подвопросы каждого блока (буллеты темы);
   - `### Умеют` → какие навыки подкрепить кодом;
   - `### Знают` / `### Понимают` → понятия для объяснения;
   - `## Проект (Kaggle)` → примеры/данные/метрика для привязки.
7. **Составить теорию** блок за блоком: каждый `Блок N` раскрывает все буллеты
   `Тема N` через подразделы (определение → формулы → код → нюансы/подводные
   камни → связь с проектом). Глубина и объём — как в эталоне (~80–120 строк
   на блок).
8. **Записать файл** `<N>_Теория.md` (кодировка UTF-8), начиная с `Блок 0. …`,
   без frontmatter, без H1, без подвала.
9. **Сообщить пользователю:** путь к файлу, список блоков `Блок N` с их
   подразделами, какие практические навыки (`Умеют`) подкреплены кодом, и явно
   отметить факты, выведенные из общих знаний (а не из материалов модуля).

## Чего избегать

- Не дублировать лекцию: теория уходит в детали, формулы и исполняемый код —
  того, чего в лекции намеренно нет.
- Не использовать markdown-заголовки `#`/`##`/`###` и не ограждать код в ` ``` `
  — формат теории определяется эталоном (метки `Блок N.` и подразделы-абзацы).
- Не сокращать блок до пересказа буллетов: каждый подвопрос раскрывается с
  определением, обоснованием и примером/кодом.
- Не вставлять в теорию формулировки задания или ячейки ноутбука — для этого
  есть `<N>_Задание.ipynb`. Код в теории — учебные иллюстрации, не заготовки
  решения соревнования целиком.
- Не повторять организационные правила курса (оценивание, антиплагиат) —
  это не относится к теории.
- Не выдумывать ссылки на видео/статьи и не копировать ссылки из Модуля 1.
- Не использовать декоративные эмодзи (только точечные ✅ / ❌ / ⚠️ как в эталоне).
- Не «лить воду»: плотность и приёмы оформления — как в `1_Теория.md`.

## Валидация

После записи убедиться, что в `<N>_Теория.md`:

1. Файл начинается с `Блок 0. …`, без frontmatter и без H1; есть блоки
   `Блок 0..N`, по одному на каждую `Тема 0..N` плана.
2. Каждый блок раскрывает все буллеты своей `Тема N` (ни один подвопрос не
   пропущен) и содержит подразделы-абзацы обычным текстом.
3. Практические навыки из `### Умеют` подкреплены кодом на Python
   (обычным текстом, без ` ``` `).
4. Есть формулы обычным текстом, английские термины в скобках, inline-код в
   обратных апострофах, маркированные/нумерованные списки.
5. Примеры и метрики привязаны к `## Проект (Kaggle)` модуля.
6. Стиль совпадает с эталоном: нет `###`-заголовков, нет ограждённого кода,
   нет эмодзи (кроме ✅/❌/⚠️), нет подвала/заключения.
