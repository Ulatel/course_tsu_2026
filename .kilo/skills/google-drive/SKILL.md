# Навык: Изучение документов проекта в Google Drive

## Папка материалов курса

Все материалы проекта `course_tsu_2026` (курс ТГУ 2026) лежат в Google Drive:

- Веб-ссылка: https://drive.google.com/drive/u/3/folders/1RWU5ftYq4GnBKuaOxkKdfPzhAVairBlt
- ID корневой папки: `1RWU5ftYq4GnBKuaOxkKdfPzhAVairBlt`
- Сегмент `u/3` в URL — это индекс Google-аккаунта пользователя (личный, не передавать агенту).

Если пользователь даёт прямую ссылку на конкретный документ внутри этой папки — работай с ней по правилам ниже.

## Главное правило доступа

Контент Google Drive защищён авторизацией. Агент **не может** залогиниться в аккаунт пользователя. Поэтому:

1. Если доступен **API-ключ** (см. раздел «API-ключ» ниже) — используй его для листинга папки и API-вызовов.
2. Иначе попробуй достать текст через **прямые экспорт-ссылки** (см. ниже) инструментом `webfetch`.
3. Если экспорт-ссылка возвращает страницу входа Google, ошибку 403/404 или пустой/JS-функциональный HTML — значит документ **не опубликован** (доступ ограничен). Не повторяй запросы вслепую.
4. В этом случае **попроси пользователя** одним из способов:
   - сделать документ доступным «по ссылке» (Файл → Доступ → «Все, у кого есть ссылка» → Читатель), **либо**
   - скачать/экспортировать файл локально в репозиторий (например в `docs/` или временную папку) и указать путь, **либо**
   - вставить содержимое прямо в чат.

## API-ключ

Для листинга папки и чтения публичных файлов используется **API-ключ Google Drive** (read-only).

- Ключ лежит в **переменной окружения** `GOOGLE_DRIVE_API_KEY`.
- **Никогда не пиши сам ключ в файлы навыка или репозиторий** — только имя переменной.
- Чтобы получить значение ключа в сессии, выполни в bash:
  - Linux/macOS: `echo "$GOOGLE_DRIVE_API_KEY"`
  - Windows PowerShell: `echo $env:GOOGLE_DRIVE_API_KEY`
- Источник значения: файл `.env` в корне репозитория (он в `.gitignore` и не коммитится). При пустой переменной сообщи пользователю, что ключ не задан, и попроси вписать его в `.env`.
- Ключ подставляется как query-параметр `key=...` в URL Drive API v3. Это работает только с `webfetch`, так как ключ передаётся прямо в URL (Bearer-токен через заголовок webfetch отправить не может — поэтому OAuth не используем).

## Шаблоны экспорт-ссылок

Извлеки `{ID}` из исходного URL и подставь в нужный шаблон.

### Google Docs (`docs.google.com/document/d/{ID}`)
- Текст: `https://docs.google.com/document/d/{ID}/export?format=txt`
- Markdown: `https://docs.google.com/document/d/{ID}/export?format=md`
- HTML: `https://docs.google.com/document/d/{ID}/export?format=html`
- PDF: `https://docs.google.com/document/d/{ID}/export?format=pdf`

### Google Sheets (`docs.google.com/spreadsheets/d/{ID}`)
- CSV первого листа: `https://docs.google.com/spreadsheets/d/{ID}/export?format=csv`
- Конкретный лист по `gid`: `.../export?format=csv&gid={GID}`
- TSV: `.../export?format=tsv`
- XLSX: `.../export?format=xlsx`

### Google Slides (`docs.google.com/presentation/d/{ID}`)
- Текст: `https://docs.google.com/presentation/d/{ID}/export?format=txt`
- PDF: `.../export?format=pdf`

### Произвольный файл в Drive (`drive.google.com/file/d/{ID}`)
- Прямое скачивание: `https://drive.google.com/uc?export=download&id={ID}`
- Для PDF/текста удобно скачать локально и прочитать через `read`.

### Содержимое публичной папки
Список файлов публичной папки (открытой «по ссылке») получается через Drive API v3 с API-ключом:
`https://www.googleapis.com/drive/v3/files?q=%27{FOLDER_ID}%27+in+parents&key={API_KEY}&fields=files(id,name,mimeType)&pageSize=200`

Где `{API_KEY}` — значение из переменной окружения `GOOGLE_DRIVE_API_KEY` (см. раздел «API-ключ»). Без ключа Drive API возвращает 403. Возвращает JSON со списком файлов.

Для обхода вложенных папок: находишь в ответе `mimeType == 'application/vnd.google-apps.folder'`, берёшь её `id` и повторяешь запрос с этим `id` в `q=...`.

## Как извлекать `{ID}` из URL

| Формат URL                                         | Где ID                         |
|----------------------------------------------------|--------------------------------|
| `drive.google.com/drive/u/N/folders/{ID}`          | после `/folders/`              |
| `drive.google.com/file/d/{ID}/view`                | после `/d/`                    |
| `docs.google.com/document/d/{ID}/edit`             | после `/d/`                    |
| `docs.google.com/spreadsheets/d/{ID}/edit`         | после `/d/`                    |
| `docs.google.com/presentation/d/{ID}/edit`         | после `/d/`                    |

ID — длинная строка из букв/цифр до следующего `/`.

## Рабочий процесс

1. Уточни у пользователя ссылку на конкретный документ или название нужного файла.
2. Определи тип документа по домену/пути URL.
3. Сформируй экспорт-ссылку (текстовый формат优先 — `txt`/`csv`/`md`, он легче парсится).
4. Загрузи через `webfetch` (формат `text` или `markdown`).
5. Если доступ закрыт — сообщи пользователю и предложи один из вариантов из «Главного правила доступа».
6. Сохраняй выжимку ключевых фактов из изученных документов, чтобы не перечитывать повторно.

## Кеширование

Если один и тот же документ читается повторно в рамках сессии — не делай повторный `webfetch`, используй уже полученное ранее содержимое. Содержимое Google Drive может меняться, поэтому при явной просьбе «перечитать свежую версию» — обновляй.

## Чего не делать

- Не пытаться логиниться в Google или вводить учётные данные.
- Не запускать браузер/Headless Chrome для обхода авторизации.
- Не гадать по содержимому, если документ не загрузился — лучше переспросить пользователя.
