# Навык: Составление плана тем для модуля курса

## Назначение

У каждого модуля курса в папке `Модуль N. <Название>/` лежит файл `<N>_План.md` (например `3_План.md`).
Базовый шаблон (`1_План.md` в `1782569085716-module-plans-ml-course.md`) содержит разделы:
`Образовательные результаты → Проект (Kaggle) → Материалы → Формат и оценивание`.

Эталонный **Модуль 1** (`Модуль 1. Введение в ML/1_План.md`) дополнительно содержит два раздела,
которые надо перенести в остальные модули:

1. `## Темы лекции. <Название лекции>` — тезисный план вводной лекции (крупный план темы). Вводная лекция проводится в самом начала модуля преподавателем и обьясняет основную базу для изучения теории модуля.
2. `## Темы теории` — разбивка теории на пронумерованные темы `### Тема N. <Название>`,
   каждая со списком конкретных подвопросов/методов/инструментов, которые студенты будут изучать самостоятельно из файла Теория.md на протяжении модуля.

Этот навык изучает `План.md` целевого модуля и **дописывает** в него эти два раздела,
выводя содержание из «Образовательных результатов», «Проекта» и «Материалов» модуля.

## Эталон

Перед составлением **обязательно** прочитать эталон `Модуль 1. Введение в ML/1_План.md`
и воспроизвести его структуру и стиль один-в-один (глубина детализации, тон, оформление списков).
Не повторять чужие темы слово в слово — брать **форму**, а содержание выводить из целевого модуля.

## Что именно добавляется (формат)

### Раздел `## Темы лекции`

```
## Темы лекции. <Название лекции>

- <крупный тезис 1: что это за область / понятие>;
- <крупный тезис 2: виды / типы / классификация подходов>;
- <крупный тезис 3: общий процесс / pipeline / принцип работы>;
- <крупный тезис 4: ключевая терминология / обозначения>;
- (опционально) <связь с проектом / предметной областью>.
```

Правила:

- **Название лекции** берётся из раздела `## Материалы` целевого модуля (поле «Лекция: …»),
  очищенное от кавычек и слова «Лекция:». Если в Материалах названия нет — сформулировать
  самостоятельно по теме модуля.
- 4–6 тезисов «крупным планом»: обзорный уровень, без кода и без мелких функций
  (это план лекции-введения, а не конспект).
- Соответствует разделам `Знают`/`Понимают` из образовательных результатов.

### Раздел `## Темы теории`

```
## Темы теории

### Тема 0. <Название>

- <конкретный подвопрос / метод / инструмент>;
- ...

### Тема 1. <Название>

- ...

### Тема 2. <Название>

- ...
```

Правила:

- Нумерация тем **сквозная**, начинается с `Тема 0`.
  По умолчанию `Тема 0` — вводная/инфраструктурная тема модуля
  (Kaggle-платформа, качество данных, метрики классификации, PyTorch, разметка данных и т.п. —
  см. таблицу ниже). Далее `Тема 1..N` — содержательные темы по нарастающей.
- Каждая тема = одна логическая глава теории с **конкретными** подвопросами:
  имена методов, алгоритмов, функций/классов библиотек (`StandardScaler`, `RandomForest`,
  `nn.Module`, autograd и т.д.), метрик, гиперпараметров.
- Количество тем: 4–6 (как в эталоне: 5 тем).
- Содержание тем должно покрывать умения из раздела `Умеют` и поддерживать выполнение
  `Проекта (Kaggle)` этого модуля.
- Подвопросы — короткие пункты через точку с запятой/точку, как в эталоне.
- Темы теории должны логически продолжать темы лекции

## Размещение в файле (важно)

Оба новых раздела вставляются **между** разделом `## Образовательные результаты`
(сразу после блока `### Понимают` с его пунктами) и разделом `## Проект (Kaggle)`:

```
### Понимают
- ...                              ← конец существующего блока

## Темы лекции. <Название>         ← ДОБАВИТЬ
- ...

## Темы теории                     ← ДОБАВИТЬ
### Тема 0. ...
- ...

## Проект (Kaggle)                 ← существующий раздел, не трогать
...
```

Реализуется через `edit`: в качестве `oldString` берётся заголовок `## Проект (Kaggle)`
(со следующей за ним строкой-описанием для уникальности), а в `newString` он предваряется
двумя новыми разделами. Это гарантирует сохранение всего существующего содержимого.

## Рабочий процесс

1. **Определить целевой модуль** из запроса (номер, название или путь).
   Файл — `<папка модуля>/<N>_План.md`. Если модуль не указан однозначно — уточнить через
   `question`, предложив список из `Модуль 2..8`.
2. **Прочитать эталон** `Модуль 1. Введение в ML/1_План.md` (форму/стиль).
3. **Прочитать целевой `<N>_План.md` целиком.**
4. **Проверить, нет ли уже разделов** `## Темы лекции` и `## Темы теории`.
   Если есть — не дублировать; сообщить пользователю и спросить, обновлять ли.
5. **Извлечь исходные данные** из целевого плана:
   - `Знают` / `Умеют` / `Понимают` → что надо разобрать;
   - `Проект (Kaggle)` → практическая задача, под которую строится теория;
   - `Материалы` → название лекции (для заголовка `## Темы лекции`) и статьи/ноутбуки.
6. **Составить `## Темы лекции`** по форме эталона; заголовок = название лекции из Материалов.
7. **Составить `## Темы теории`** из 4–6 тем `Тема 0..N` с конкретными подвопросами.
   Отталкиваться от таблицы «Содержание по модулям» ниже, уточняя под реальные
   образовательные результаты целевого плана.
8. **Вставить** оба раздела перед `## Проект (Kaggle)` через `edit`, сохранив весь остальной текст.
9. **Сообщить пользователю**: путь к файлу, название лекции, список добавленных тем `Тема N`,
   и отметить, если что-то было выведено из общих знаний (а не из явных материалов модуля).

## Содержание по модулям (опорный план)

Стартовая разбивка тем для каждого модуля — выводится из презентации курса
(см. `1782569085716-module-plans-ml-course.md`). Агент уточняет детали под реальные
«Образовательные результаты» целевого `<N>_План.md`.

### Модуль 1. Введение в ML — ЭТАЛОН (не переписывать)

- Лекция: «Что такое ML, какие бывают задачи, общий процесс обучения модели».
- Темы: 0. Работа с платформой Kaggle; 1. Знакомство с данными; 2. EDA;
  3. Обработка данных; 4. Обучение и оценка модели классификации.

### Модуль 2. Регрессия и градиентный спуск (семестр 1)

- Лекция: «Постановка задачи регрессии, процесс обучения, минимизация ошибки через градиентный спуск».
- Темы: 0. Качество данных (точность, полнота, согласованность, своевременность);
  1. Постановка задачи регрессии (непрерывная целевая переменная, признаки, примеры);
  2. Линейная регрессия и функции потерь (MSE, MAE, аналитическое решение);
  3. Градиентный спуск (производная, шаг обучения, сходимость, реализация «с нуля»);
  4. Переобучение/недообучение, регуляризация, подбор гиперпараметров;
  5. Метрики качества регрессии (MAE, RMSE, R²) и проект Kaggle House Prices.

### Модуль 3. Ансамбль. Задача классификации (семестр 1)

- Лекция: «Принцип работы ансамблей, виды ансамблей».
- Темы: 0. Метрики классификации (матрица ошибок, precision, recall, F1, ROC-AUC);
  1. Бэггинг и Random Forest (бутстреп, out-of-bag, важность признаков);
  2. Бустинг (Gradient Boosting, XGBoost / LightGBM / CatBoost);
  3. Несбалансированные классы (веса классов, овер/андерсемплинг, SMOTE);
  4. Специфика ML-задач в физике (Бозон Хиггса, поиск редких частиц);
  5. Кросс-валидация и подбор гиперпараметров ансамблей.

### Модуль 4. Нейросети и PINN (семестр 1)

- Лекция: «Введение в нейросети, решаемые задачи, обучение нейросетей; как считается loss и как его модифицировать».
- Темы: 0. Знакомство с PyTorch (тензоры, autograd, `nn.Module`, оптимизаторы);
  1. Искусственный нейрон и функции активации (ReLU, sigmoid, tanh);
  2. Многослойный перцептрон: архитектура и прямой проход (forward);
  3. Обучение нейросети (loss, оптимизатор, backprop, эпохи, батчи);
  4. Классификация изображений MNIST — учебный пример (Dataset/DataLoader, цикл обучения, переобучение, валидация, сохранение модели);
  5. Функция потерь глубже и PINN: дифференциальные уравнения, data loss + physics loss (residual, производные через autograd);
  6. Прикладная задача: прогнозирование оставшегося заряда литий-ионной батареи.

### Модуль 5. Работа с крупными моделями (семестр 2)

- Лекция: «Принципы дообучения моделей».
- Темы: 0. Разметка данных для компьютерного зрения (инструменты, форматы, bbox, маски);
  1. Аугментация данных (геометрическая, фотометрическая, Albumentations);
  2. Архитектуры CV: YOLO (детекция), UNet (сегментация);
  3. Transfer learning и fine-tuning (заморозка слоёв, дообучение классификатора);
  4. Дообучение YOLO на своих данных; 5. Обучение UNet с нуля.

### Модуль 6. Мультиагентные LLM-системы (семестр 2)

- Лекция: «LLM-агенты и мультиагентные системы: роли, инструменты, оркестрация, оценка».
- Темы: 0. LLM и API языковых моделей (трансформер обзорно, промпты, токены, стоимость, SDK);
  1. LLM-агент (цикл «планирование → действие → наблюдение», роли, память);
  2. Инструменты агента (function calling: схемы, свои функции Python, обработка ошибок);
  3. Мультиагентные архитектуры (оркестратор и исполнители, конвейер, дебаты, протокол обмена);
  4. Оценка и надёжность (метрики агентов, критик, трассировка, галлюцинации);
  5. Проектирование системы под задачу (роли, инструменты, учебный пример).

### Модуль 7. Свободное решение задачи нейросетями или классическим ML (семестр 2)

- Лекция: «Выбор модели под задачу и полный pipeline» (сформулировать, т.к. в материалах не указано).
- Темы: 0. Постановка задачи ML в предметной области (цель → ML-задача);
  1. Классический ML vs нейросети: критерии выбора (размер данных, тип задачи, интерпретируемость);
  2. Выбор метрики под задачу (бизнес-метрика → ML-метрика);
  3. Полный pipeline от данных до применения (EDA, моделирование, валидация, deploy — кратко);
  4. Работа над свободным проектом (классификация типов облаков, детекция брака и др.).

### Модуль 8. Сложные архитектуры нейронных сетей (семестр 2)

- Лекция: «Передовые архитектуры моделей: Transformer и механизм внимания подробно, GAN, GNN, Autoencoders, диффузионные модели».
- Темы: 0. Autoencoders (encoder–decoder, латентное пространство, аномалии/кластеризация);
  1. Transformer: механизм внимания (запросы/ключи/значения, multi-head, позиционные кодирования);
  2. Семейства Transformer и эмбеддинги текстов (BERT/GPT, кластеризация/классификация через энкодеры и LLM);
  3. GAN (генератор, дискриминатор, состязательное обучение);
  4. GNN (графы, свёртки на графах);
  5. Диффузионные модели (зашумление/генерация, связь с U-Net из Модуля 5).

## Стиль

- **Язык:** русский. **Без эмодзи.**
- Пункты списков — короткие, через `;` или `.`, как в эталоне.
- Имена библиотек/классов/функций — `inline code` (`StandardScaler`, `nn.Module`).
- Стрелки `→` допустимы (как в эталоне: «постановка задачи → подготовка данных → …»).
- Согласовывать с уже существующим текстом целевого плана по терминологии.

## Чего избегать

- Не перезаписывать и не удалять существующие разделы плана.
- Не дублировать разделы, если они уже есть.
- Не дублировать темы лекции в теории.
- Не вставлять код-сниппеты (это план тем, а не конспект теории — для конспектов есть агент `edu-writer`).
- Не «лить воду»: плотность и объём — как в эталоне `1_План.md`.
- Не выдумывать название лекции, если оно есть в `## Материалы`.

## Валидация

После вставки убедиться, что в целевом `<N>_План.md`:

1. Появились `## Темы лекции. <Название>` и `## Темы теории` с темами `Тема 0..N`.
2. Разделы стоят между `### Понимают` и `## Проект (Kaggle)`.
3. Все исходные разделы (`Образовательные результаты`, `Проект`, `Материалы`,
   `Формат и оценивание`) сохранены без изменений.
4. Темы теории покрывают пункты `Умеют` и подготавливают к `Проекту (Kaggle)`.
