# Навык: Написание полного текста лекции модуля

## Назначение

В каждом модуле курса в папке `Модуль N. <Название>/` лежит файл `<N>_Лекция.md`
(например `2_Лекция.md`) — **полный текст вводной лекции** модуля.

Вводная лекция проводится преподавателем в самом начале модуля и объясняет базу
для самостоятельного изучения теории (`<N>_Теория.md`). Это **не** конспект теории,
**не** слайды (`<N>_Лекция.pptx`) и **не** задание (`<N>_Задание.ipynb`) —
это связный читаемый текст лекции, который можно «прочитать со сцены».

Лекция должна быть расчитана на 90 минут.

Эталон формы и стиля — `Модуль 1. Введение в ML/1_Лекция.md`. Этот навык читает
`<N>_План.md` целевого модуля и **создаёт** `<N>_Лекция.md`, разворачивая раздел
`## Темы лекции` плана в полноценный текст лекции.

## Эталон

Перед написанием **обязательно** прочитать `Модуль 1. Введение в ML/1_Лекция.md`
и воспроизвести его форму и стиль один-в-один (заголовки, ЧАСТИ, сквозная нумерация
подразделов, таблицы, ASCII-схемы, заключение, подвал). Берётся **форма**;
содержание выводится из целевого плана и собственных знаний по теме модуля.
Не повторять тему Модуля 1 дословно — переносить приёмы оформления.

## Источник содержания

Содержание лекции выводится из целевого `<N>_План.md`:

- `## Темы лекции. <Название>` — **каркас** лекции: каждый тезис = тема
  части/подраздела; `<Название>` → заголовок и H1 лекции.
- `## Образовательные результаты` (Знают / Умеют / Понимают) — что лекция должна
  объяснить; уровень **обзорный**, как в эталоне (без глубокой теории).
- `## Проект (Kaggle)` — практическая задача модуля; лекция в финальной части
  связывает теорию с этим проектом.
- `## Материалы` — название лекции, если его нет в `## Темы лекции`.
- `## Темы теории` — чтобы **не дублировать** глубокую теорию: лекция даёт обзор
  и интуицию, а детали (вывод формул, код, гиперпараметры) остаются для
  `<N>_Теория.md`.

## Структура лекции (по эталону)

Лекция строится из ЧАСТЕЙ (`## ЧАСТЬ <римская>. <НАЗВАНИЕ>`), внутри —
пронумерованные слайды (`#### N. <Название>`). Нумерация слайдов **сквозная**
по всей лекции (1, 2, 3, … до конца), без обнуления в каждой части

Общий каркас:

1. **Вступительный абзац** — 1–2 строки: о чём лекция, для какого модуля, как
   структурирована (по образцу строки 2 эталона: «Это вводная лекция …
   Ниже представлен полный текст лекции, структурированный по разделам:»).
2. Горизонтальная линия `---`.
3. `# **ПОЛНЫЙ ТЕКСТ ЛЕКЦИИ: <НАЗВАНИЕ ВСЕМИ ЗАГЛАВНЫМИ>**`.
4. **ЧАСТЬ I** — вводная часть:
   - **Только для Модуля 1** (первая лекция курса): полная организационная часть
     как в эталоне — общая информация о курсе (преподаватель, формат, проект,
     расписание), система оценивания (100 баллов, порог 60, 2 показа прогресса,
     штраф −20), правила использования чужого кода, работа с LLM (✅/❌).
   - **Для модулей 2–8**: краткий «контекст и место модуля в курсе» — связь с
     предыдущим модулем, зачем нужна эта тема, цели лекции, что студенты будут
     делать в проекте модуля. Организационные правила (оценивание, антиплагиат,
     защита, показы прогресса) **не повторять** — они даны в Модуле 1.
5. **Содержательные ЧАСТИ** — по тезисам `## Темы лекции`. Каждый тезис
   разворачивается в 1–2 подраздела с бытовыми примерами, таблицами, схемами.
   Покрывают пункты `Знают` / `Понимают`. Каждая часть должна быть связным цельным текстом, готовым к четнию со сцены
6. **Финальная ЧАСТЬ — проект (Kaggle)** — связать тему модуля с его задачей из
   `## Проект (Kaggle)`: что предсказываем, тип задачи (бинарная/многоклассовая
   классификация, регрессия, …), этапы pipeline. По образцу ЧАСТИ V эталона
   (Titanic) — с историческим/предметным контекстом задачи и этапами работы над
   ML-проектом.
7. `## **ЗАКЛЮЧЕНИЕ**` — нумерованный список итогов (какой фундамент заложила
   лекция) + блок **Следующие шаги** (что студенты будут делать в теории и проекте).

## Стиль (строго по эталону `1_Лекция.md`)

- **Язык:** русский.
- **Заголовки — жирные:**
  - H1: `# **ПОЛНЫЙ ТЕКСТ ЛЕКЦИИ: <НАЗВАНИЕ>**` (ALL CAPS).
  - Часть: `## **ЧАСТЬ <римская>. <НАЗВАНИЕ>**` (ALL CAPS), `## **ЗАКЛЮЧЕНИЕ**`.
  - Слайд: `#### **N. <Название>**` (сквозная нумерация).
- **Термины:** `**жирный**` при первом упоминании; английский термин в скобках
  (`обучающая выборка (Training Dataset)`).
- **Списки:** маркированные `-` и нумерованные `1.`; стилизованные метки
  `**Условие 1:**`, `**Критерий 1:**`, `**Пример — ...:**`, `**Определение:**`.
- **Таблицы:** markdown-таблицы для сравнений и «примеров из жизни»
  (как `Контекст / Накопленный опыт / Состояние мира / Решение`).
- **ASCII-схемы:** в блоках ` ``` ` — иерархии (AI → ML → DL), дерево
  классификации видов обучения, pipeline, базовая схема
  «признаки → модель → предсказание».
- **Цитаты:** `> Ключевая фраза: …` для выделения главного тезиса.
- **Математика:** текстовые формулы
- **Маркеры ✅ / ❌ / ⚠️:** допустимы ровно как в эталоне (хороший/плохой пример,
  предупреждение). Других эмодзи **не использовать**.
- **«Вопросы залу»** — отдельный подраздел с вопросом залу, помогающий усвоить материал. Вставлять там, где это поучительно.
- **Горизонтальные линии** `---` между подразделами.
- **Тон:** педагогический, с бытовыми метафорами и примерами (прогноз погоды,
  рекомендации видео, шахматы и т.п.), по существу, без воды.

## Рабочий процесс

1. **Определить целевой модуль** из запроса (номер, название или путь).
   Файл — `<папка модуля>/<N>_Лекция.md`. Если модуль не указан однозначно —
   уточнить через `question`, предложив список `Модуль 2..8` (Модуль 1 уже есть).
2. **Прочитать эталон** `Модуль 1. Введение в ML/1_Лекция.md` (форму/стиль).
3. **Прочитать целевой `<N>_План.md` целиком.**
4. **Проверить, существует ли уже `<N>_Лекция.md`.**
   - Если существует и в запросе не было явного «переписать» — уточнить у
     пользователя (дописать / переписать / отмена).
   - Для нового файла — писать с нуля.
5. **Извлечь исходные данные** из плана:
   - `## Темы лекции` → каркас (тезисы) + название лекции;
   - `## Образовательные результаты` → что покрыть;
   - `## Проект (Kaggle)` → финальная часть;
   - `## Темы теории` → граница «лекция обзор / теория подробно».
6. **Составить лекцию** по каркасу выше: ЧАСТЬ I (адаптивно — см. п. 4
   структуры), содержательные части, часть про проект, ЗАКЛЮЧЕНИЕ, подвал.
   Подразделы нумеровать сквозной нумерацией.
7. **Записать файл** `<N>_Лекция.md` (кодировка UTF-8).
8. **Сообщить пользователю:** путь к файлу, название лекции, список ЧАСТЕЙ с
   диапазонами номеров подразделов, и явно отметить факты, выведенные из общих
   знаний (а не из материалов модуля), а также использованные бытовые примеры.

## Чего избегать

- Не дублировать глубокую теорию из `## Темы теории` — лекция обзорная,
  без вывода формул и без обучающего кода.
- Не вставлять исполняемый Python-код (для него есть `<N>_Теория.md` /
  `<N>_Задание.ipynb`); допускаются только псевдокод и ASCII-схемы в блоках ` ``` `.
- Не повторять организационные правила курса (оценивание, антиплагиат, защита,
  показы прогресса, работа с LLM) в модулях 2–8 — это только для Модуля 1.
- Не выдумывать факты: конкретные цифры, даты, историю без источника подавать
  как обобщённый пример и отмечать это.
- Не использовать декоративные эмодзи (только ✅ / ❌ / ⚠️ как в эталоне).
- Не «лить воду»: плотность и приёмы оформления — как в `1_Лекция.md`.

## Валидация

После записи убедиться, что в `<N>_Лекция.md`:

1. Есть вступительный абзац, `# ПОЛНЫЙ ТЕКСТ ЛЕКЦИИ: …`, ЧАСТИ с римскими
   номерами и `## ЗАКЛЮЧЕНИЕ`.
2. Слайды `#### N.` пронумерованы сквозной нумерацией без пропусков и
   повторов.
3. Содержание покрывает тезисы `## Темы лекции` и пункты `Знают` / `Понимают`.
4. Есть связка с `## Проект (Kaggle)` модуля (что предсказываем, тип задачи).
5. Стиль совпадает с эталоном (таблицы, хотя бы одна ASCII-схема, маркеры
   ✅/❌, жирные термины с английским в скобках, подвал с автором и вузом).
