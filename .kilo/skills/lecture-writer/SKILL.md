# Навык: Написание полного текста лекции модуля

## Назначение

В каждом модуле курса в папке `Модуль N. <Название>/` лежит файл `<N>_Лекция.md`
(например `2_Лекция.md`) — **полный текст вводной лекции** модуля.

Это **связный текст выступления**, который можно «прочитать со сцены»: лекция идёт
в первой половине модуля и даёт обзорную базу для самостоятельного изучения теории
(`<N>_Теория.md`). Это **не** конспект теории, **не** слайды (`<N>_Лекция.pptx`) и
**не** задание (`<N>_Задание.ipynb`).

Лекция рассчитана примерно на 90 минут и подаётся как разговорная речь, разбитая
на «слайды» — короткие смысловые блоки.

Эталон формы и стиля — `Модуль 1. Введение в ML/1_Лекция.md`. Этот навык читает
`<N>_План.md` целевого модуля и **создаёт** `<N>_Лекция.md`, разворачивая раздел
`## Темы лекции` плана в полноценный текст лекции **строго в форме эталона**.

## Эталон (обязательно к воспроизведению один-в-один)

Перед написанием **обязательно** прочитать `Модуль 1. Введение в ML/1_Лекция.md`
целиком и воспроизвести его форму и стиль один-в-один. Ниже зафиксированы все
приёмы оформления эталона; отступать от них нельзя.

Переносится **только форма** (заголовок, блок-вступление, «Часть N», метки слайдов,
разговорный тон, завершение, подвал). Содержание выводится из целевого плана и
собственных знаний по теме модуля — тему Модуля 1 дословно не повторять.

## Источник содержания

Содержание лекции выводится из целевого `<N>_План.md`:

- `## Темы лекции. <Название>` — **каркас** лекции: каждый тезис = тема части;
  `<Название>` → заголовок H1 лекции.
- `## Образовательные результаты` (Знают / Умеют / Понимают) — что лекция должна
  объяснить; уровень **обзорный**, как в эталоне (без глубокой теории).
- `## Проект (Kaggle)` — практическая задача модуля; лекция в финальной части
  связывает теорию с этим проектом.
- `## Материалы` — название лекции, если его нет в `## Темы лекции`.
- `## Темы теории` — чтобы **не дублировать** глубокую теорию: лекция даёт обзор
  и интуицию, а детали (вывод формул, код, гиперпараметры) остаются для
  `<N>_Теория.md`.

## Структура лекции (по эталону)

Лекция состоит из ЧАСТЕЙ (`## Часть N. <Название>`), а внутри частей текст разбит
на «слайды» — короткие абзацы-блоки, каждый начинается меткой слайда. Нумерация
слайдов **сквозная** по всей лекции (1, 2, 3, … до конца), без обнуления в каждой
части. Целевой объём — примерно **60–90 слайдов** на 90-минутную лекцию.

Общий каркас:

1. **H1** — `# Текст лекции. Модуль N. <Название модуля>` (в точности как
   `# Текст лекции. Модуль 1. Введение в ML`).
2. **Блок-вступление** — цитата `>` из 4 строк. Первые 2 строки адаптируются под
   сгенерированный текст, последние 2 — **дословно** как в эталоне:
   ```
   > Текст вводной лекции модуля N. <Название> (M слайдов).
   > Текст написан как связное выступление и разбит на слайды для будущей презентации.
   > Метки `[Слайд N]` отмечают переход по слайдам, чтобы синхронизировать чтение с презентацией.
   > Слайды с рисунками/диаграммами без текста отмечены как `[иллюстрация]`.
   ```
   Для Модуля 1 — оставить оригинальное вступление эталона (про заметки на слайдах
   `.pptx` и дословность).
3. Горизонтальная линия `---`.
4. **Части** `## Часть N. <Название>` (N — арабское число, 1, 2, 3 …; название —
   обычным регистром, как «О курсе», «Базовые термины»).
   - **Часть 1.** Для Модуля 1 — полная организационная часть как в эталоне (о
     курсе, формат, проект, расписание, оценивание 100 баллов / порог 60 / 2
     показа прогресса / штраф −20, правила чужого кода, работа с LLM). Для
     модулей 2–8 — **краткое** вступление: связь с прошлым модулем, зачем нужна
     эта тема, цели лекции, что студенты делают в проекте модуля.
     Организационные правила (оценивание, антиплагиат, показы прогресса, работа с
     LLM) **не повторять** — они даны в Модуле 1.
   - **Содержательные части** — по тезисам `## Темы лекции`. Один тезис обычно
     становится одной Частью, но ради связного повествования тезис можно
     разбить на несколько частей или, наоборот, объединить (в эталоне 8 тезисов
     → 11 частей). Каждая часть — связный цельный текст, готовый к чтению со
     сцены, с бытовыми примерами.
   - **Финальная часть — проект (Kaggle)** — связывает тему модуля с задачей из
     `## Проект (Kaggle)`: что предсказываем, тип задачи (регрессия, бинарная/
     многоклассовая классификация, …), предметный/исторический контекст и этапы
     ML-пайплайна (по образцу Части 11 эталона — «Титаник»).
5. **Завершение** — последний слайд: `[Слайд M] Спасибо за внимание.` (как
   `[Слайд 93] Спасибо за внимание.` в эталоне).
6. **Подвал** (необязательно) — цитата `>` с примечанием: что было добавлено сверх
   плана, какие бытовые примеры выведены из общих знаний, иные пояснения. По форме
   как подвал эталона (`> Примечание: …`). Если примечаний нет — блок опускается.

## Разметка слайдов (строго по эталону)

- **Один слайд:** `[Слайд 14]` в начале абзаца-блока.
- **Диапазон слайдов:** `[Слайды 15–17]` — с **тире** `–` (en-dash), не дефисом.
- Метка ставится **в начале** того абзаца, который она обозначает.
- Слайд = один короткий смысловой блок (обычно 1–4 предложения), иногда целый
  абзац. Между метками — пустая строка.
- **Слайд-картинка:** `` `[иллюстрация]` `` (в обратных кавычках). Ставится либо
  отдельной строкой `[]` для слайда, который целиком рисунок/диаграмма без текста,
  либо в конце текста слайда, если к тексту прилагается визуал
  (`… материал стен). \`[иллюстрация]\``).
- Допустимо, чтобы мысль перетекала через границу слайдов (как в эталоне: фраза
  начинается на одном слайде и продолжается на следующем) — это естественный
  живой ритм выступления.

## Стиль (строго по эталону `1_Лекция.md`)

- **Язык:** русский.
- **Тон:** разговорный, как устное выступление. Первое лицо и «мы с вами»
  («давайте разберёмся», «посмотрим на пример», «вернёмся к»). Бытовые метафоры и
  примеры (прогноз погоды, рекомендации видео, шахматы, цена дома и т. п.). По
  существу, без воды и без канцелярита.
- **Заголовки:**
  - H1: `# Текст лекции. Модуль N. <Название>`.
  - Часть: `## Часть N. <Название>` (арабское число, обычный регистр).
  - **Никаких** подзаголовков `###`/`####` внутри частей — только метки слайдов.
- **Термины:** `**жирный**` при первом упоминании; английский термин в скобках —
  `обучающая выборка (Training Dataset)`, `целевая переменная (target)`,
  `проклятие размерности (Curse of Dimensionality)`.
- **Списки:** маркированные `-` и нумерованные `1.` для перечислений (этапы
  алгоритма, шаги пайплайна, примеры). Стилизованные вводные метки жирными:
  `**Проблема 1.** …`, `**Переобучение** — …`.
- **Проверки залу:** уместны как естественный приём прямо в прозе («Небольшая
  проверка — к какому типу задач относятся примеры: …»), без отдельного
  подраздела-заголовка.
- **Математика:** только **текстом в прозе** (`k = 3`, `k = 6`, `N свечей`),
  формулы — простым текстом (`y = w₀ + w₁·x₁ + … + wₙ·xₙ`). **Без** блоков LaTeX
  (`$…$`, `$$…$$`).
- **Цитаты `>`:** только для блок-вступления (п. 2 структуры) и подвала (п. 6).
  Не использовать внутри частей (никаких «> Ключевая фраза: …»).
- **Эмодзи:** **не использовать** (никаких ✅ / ❌ / ⚠️ и прочих).
- **Таблицы и ASCII-схемы:** **не использовать**. Сравнения и схемы подаются
  прозой или списками; там, где в презентации был бы рисунок/диаграмма, ставится
  `` `[иллюстрация]` ``.

## Рабочий процесс

1. **Определить целевой модуль** из запроса (номер, название или путь).
   Файл — `<папка модуля>/<N>_Лекция.md`. Если модуль не указан однозначно —
   уточнить через `question`, предложив список `Модуль 2..8` (Модуль 1 уже есть).
2. **Прочитать эталон** `Модуль 1. Введение в ML/1_Лекция.md` целиком (форму/стиль).
3. **Прочитать целевой `<N>_План.md` целиком.**
4. **Проверить, существует ли уже `<N>_Лекция.md`.**
   - Если существует и в запросе не было явного «переписать» — уточнить у
     пользователя (дописать / переписать / отмена).
   - Для нового файла — писать с нуля.
5. **Извлечь исходные данные** из плана:
   - `## Темы лекции` → каркас (тезисы) + название лекции;
   - `## Образовательные результаты` → что покрыть;
   - `## Проект (Kaggle)` → финальная часть;
   - `## Темы теории` → граница «лекция обзор / теория подробно».
6. **Составить лекцию** по каркасу выше: H1, блок-вступление, `---`, Часть 1
   (адаптивно — см. п. 4 структуры), содержательные части, финальная часть про
   проект, завершение «Спасибо за внимание.», при необходимости подвал. Слайды
   нумеровать сквозной нумерацией.
7. **Записать файл** `<N>_Лекция.md` (кодировка UTF-8).
8. **Сообщить пользователю:** путь к файлу, название лекции, число слайдов,
   список Частей с диапазонами номеров слайдов, и явно отметить факты, выведенные
   из общих знаний (а не из материалов модуля), а также использованные бытовые
   примеры.

## Чего избегать

- Не дублировать глубокую теорию из `## Темы теории` — лекция обзорная, без
  вывода формул и без обучающего кода.
- Не вставлять исполняемый Python-код (для него есть `<N>_Теория.md` /
  `<N>_Задание.ipynb`); допускается только псевдокод простым текстом.
- Не повторять организационные правила курса (оценивание, антиплагиат, защита,
  показы прогресса, работа с LLM) в модулях 2–8 — это только для Модуля 1.
- Не выдумывать факты: конкретные цифры, даты, историю без источника подавать
  как обобщённый пример и отмечать это в подвале.
- Не использовать формальный «учебниковый» формат: никаких `# ПОЛНЫЙ ТЕКСТ
  ЛЕКЦИИ:`, `## ЧАСТЬ I.`, подзаголовков `###`/`####`, таблиц, ASCII-схем, блоков
  LaTeX, эмодзи (✅/❌/⚠️), блоков `> Ключевая фраза:`. Это всё **не** в эталоне.
- Не «лить воду»: плотность и приёмы оформления — как в `1_Лекция.md`.

## Валидация

После записи убедиться, что в `<N>_Лекция.md`:

1. Заголовок — `# Текст лекции. Модуль N. <Название>`, затем блок-вступление `>` и
   `---`.
2. Части — `## Часть N. <Название>` (арабские числа, обычный регистр); нет
   подзаголовков `###`/`####`.
3. Слайды отмечены `[Слайд N]` / `[Слайды N–M]` (en-dash), пронумерованы сквозной
   нумерацией без пропусков и повторов; завершаются `[Слайд M] Спасибо за внимание.`
4. Есть хотя бы один `` `[иллюстрация]` `` там, где по теме естественно был бы
   рисунок/диаграмма.
5. Содержание покрывает тезисы `## Темы лекции` и пункты `Знают` / `Понимают`;
   есть связка с `## Проект (Kaggle)` (что предсказываем, тип задачи).
6. Стиль совпадает с эталоном: разговорная проза, жирные термины с английским в
   скобках, нумерованные/маркированные списки. **Нет** таблиц, ASCII-схем, LaTeX,
   эмодзи и `> Ключевая фраза:`.
