# Навык: Генерация презентации модуля (.pptx)

## Назначение

В каждом модуле курса в папке `Модуль N. <Название>/` лежит файл `<N>_Лекция.pptx`
(например `2_Лекция.pptx`) — **слайды вводной лекции** модуля, которые преподаватель
показывает студентам на занятии.

Эталон формы — `Модуль 1. Введение в ML/1_Лекция.pptx` (78 слайдов, ручная вёрстка,
экспорт из Google Slides). Этот навык **не пытается** с нуля воспроизвести всю
ручную графику эталона (иллюстрации, диаграммы, декоративные группы). Вместо этого
он генерирует **чистую, единообразно оформленную текстовую колоду** в фирменном
стиле курса поверх эталон-шаблона, а всю ручную графику оставляет как отдельный
шаг «доработать вручную».

Источник содержания — файл `<N>_Лекция.md`: связный текст выступления с маркерами
`[Слайд N]` / `[Слайды N–M]`, синхронизирующими чтение с презентацией. В эталоне
полный текст выступления хранится именно в **заметках слайдов (notes)**, а на самих
слайдах — краткие тезисы. Этот навык воспроизводит ту же модель.

## Эталон и дизайн-токены

Все токены извлечены из `1_Лекция.pptx` и зашиты в генератор
`generate_pptx.py` — вручную их задавать не нужно:

| Токен | Значение |
|---|---|
| Размер слайда | 16:9, 13.33 × 7.5 дюймов (widescreen) |
| Мастер / тема | `simple-light-2` (берётся из шаблона `1_Лекция.pptx`) |
| Основной шрифт | **IBM Plex Sans** |
| Заголовок слайда | 36 pt, bold, цвет `#15110E` |
| Тело слайда | 16 pt, цвет `#000000` |
| Слайд-раздел (`## Часть`) | 44 pt, bold, фирменный фиолетовый `#8E39E2` |
| Титульный слайд | 44 pt (название) + 20 pt (подзаголовок, акцент) |
| Акцент / бейджи | `#8E39E2` (фиолетовый); фон слайдов — светлый `#FFFAF6` (в теме) |

## Связь файлов

```
<N>_Лекция.md   →  (этот навык)  →  <N>_Лекция.pptx
[N_xотбы текст выступления + маркеры слайдов]     [слайды: заголовок + тезисы + notes]
```

- `# Текст лекции. …` (H1) → **титульный слайд** (layout `TITLE`).
- `## Часть X. <Название>` → **слайд-раздел** (layout `SECTION_HEADER`, фиолетовый).
- `[Слайд N] текст…` / `[Слайды N–M] текст…` → **контентный слайд** (layout `OBJECT`):
  заголовок = текущая `Часть`; тело = короткая выжимка; **notes = полный текст**.
- `[иллюстрация]` (или пустой маркер) → **слайд-заглушка**
  «[Иллюстрация — вставить вручную]».

## Что делает генератор и что остаётся за агентом

**Генератор `generate_pptx.py` (автоматически):**
- Открывает эталон `1_Лекция.pptx` как шаблон (тема + мастер + раскладки).
- Удаляет все слайды шаблона, оставляя чистую колоду с темой.
- Парсит `<N>_Лекция.md` и строит слайды по правилам выше.
- Применяет фирменные шрифты/размеры/цвета.
- Кладёт полный текст каждого слайда в **notes**.

**Агент (вручную после генерации):**
- **Перерабатывает тело слайдов** из первой-попавшейся фразы в **краткие тезисы**
  (см. «Правила переработки»): генератор ставит туда лишь заглушку-первое
  предложение — это не финальный текст слайда.
- Подставляет **осмысленные заголовки слайдов** вместо названия части, где это
  уместно (например «Обучение с учителем», а не «Часть 8»).
- Заменяет слайды-заглушки `[Иллюстрация — вставить вручную]` реальными рисунками/
  диаграммами в Google Slides / PowerPoint (ASCII-схемы из лекции можно
  перерисовать простыми автофигурами).
- Проверяет, что текст не вылезает за слайд (длинные абзацы → ужать до тезисов).

## Инструмент: `generate_pptx.py`

Скрипт лежит рядом с этим файлом: `.kilo/skills/pptx-writer/generate_pptx.py`.

Зависимость: `python-pptx` (`pip install python-pptx`). Python 3.8+.

Запуск из корня репозитория:

```bash
python ".kilo/skills/pptx-writer/generate_pptx.py" \
  "Модуль 2. Регрессия и градиентный спуск/2_Лекция.md" \
  "Модуль 2. Регрессия и градиентный спуск/2_Лекция.pptx"
```

Ключ `--template` переопределяет эталон (по умолчанию
`Модуль 1. Введение в ML\1_Лекция.pptx`):

```bash
python ".kilo/skills/pptx-writer/generate_pptx.py" <LECTURE.md> <OUT.pptx> --template <TEMPLATE.pptx>
```

Скрипт печатает сводку: число титулов / разделов / контентных слайдов / заглушек-иллюстраций.

## Рабочий процесс

1. **Определить целевой модуль** из запроса (номер, название или путь).
   Файл результата — `<папка модуля>/<N>_Лекция.pptx`. Если модуль не указан
   однозначно — уточнить через `question`, предложив `Модуль 2..8`.
2. **Убедиться, что есть исходник** `<N>_Лекция.md` с маркерами `[Слайд N]`.
   - Если его нет — сначала применить навык `lecture-writer`.
   - Если лекция не размечена маркерами `[Слайд N]`, попросить пользователя
     разметить (или уточнить, разбивать ли текст на слайды автоматически).
3. **Проверить, существует ли уже `<N>_Лекция.pptx`.**
   - Если существует и в запросе не было явного «пересобрать/перезаписать» —
     уточнить у пользователя (пересобрать / дополнить / отмена). Пересборка
     затирает весь файл.
4. **Убедиться в окружении:** `python` доступен и установлен `python-pptx`
   (`python -c "import pptx"`). Если нет — `pip install python-pptx`.
5. **Запустить генератор** (команда выше) и дождаться сводки по слайдам.
6. **Переработать слайды** (главный шаг качества): открыть `<N>_Лекция.pptx`
   через python-pptx (скриптом или правкой) и для каждого контентного слайда
   заменить заглушку-тело на 3–6 кратких тезисов, заголовок сделать осмысленным.
   Текст в notes при этом **сохранять** — это текст выступления.
7. **Иллюстрации:** оставить слайды-заглушки видимыми в файле как напоминание;
   отметить пользователю, какие слайды требуют ручной графики.
8. **Сообщить пользователю:** путь к файлу, число слайдов по типам, список
   слайдов-заглушек (нужны иллюстрации), и явно сказать, что декоративная
   графика эталона в сгенерированном файле отсутствует и добавляется вручную.

## Правила переработки текста (выступление → тезисы слайда)

В эталоне слайд = краткая выжимка, а notes = полный текст. Перерабатывая тело
слайда, придерживаться:

- **1 слайд = 1 мысль.** Не класть на один слайд несколько независимых тем —
  лучше разбить (в лекции им соответствуют разные `[Слайд N]`).
- **3–6 тезисов**, каждый в одну-две строки; не копировать абзац целиком.
- Ключевые термины — **жирным**; английский термин в скобках, как в лекции
  (`обучающая выборка (Training Dataset)`).
- Списки — маркированные (если перечисление) или нумерованные (если шаги/этапы).
- Цифры/факты из лекции переносить точечно (баллы, пороги, даты), без воды.
- Если в notes длинный абзац про одно понятие — на слайде вынести **определение**
  одной строкой и 2–3 признака списком.
- Маркеры `✅ / ❌ / ⚠️` допустимы точечно (как в материалах курса); других
  эмодзи не использовать.

## Чего избегать

- **Не пытаться сгенерировать декоративную графику эталона** (картинки, диаграммы,
  правую декоративную колонку, бейджи). Это ручная работа в редакторе — скилл
  честно оставляет её как отдельный шаг.
- Не копировать весь абзац из лекции в видимое тело слайда — слайд не читается.
  Полный текст живёт в notes; на слайде — тезисы.
- Не менять тему/мастер: стиль берётся строго из шаблона `1_Лекция.pptx`,
  чтобы колоды модулей выглядели единообразно.
- Не удалять и не сокращать notes — это текст выступления преподавателя.
- Не «лить воду»: плотность — как в эталоне `1_Лекция.pptx`.
- Не выдумывать факты: содержание берётся из `<N>_Лекция.md`; чего там нет —
  не добавлять.

## Валидация

После генерации и переработки убедиться, что в `<N>_Лекция.pptx`:

1. Файл открывается без ошибок (валидный `.pptx`); размер слайда 16:9.
2. Есть титульный слайд, слайды-разделы по числу `## Часть` в лекции,
   контентные слайды по числу слайд-маркеров.
3. Каждый контентный слайд: осмысленный заголовок (IBM Plex Sans, 36 pt, bold) +
   краткие тезисы в теле, а полный текст — в **notes** слайда.
4. Все `[иллюстрация]` из лекции отражены слайдами-заглушками (или реальной
   графикой), ни один маркер не потерян.
5. Стиль единообразен: IBM Plex Sans, фиолетовый акцент `#8E39E2` на разделах,
  чёрный основной текст; нет «сломанных» шрифтов/размеров.
6. Пользователю сообщено, какие слайды требуют ручного добавления иллюстраций.
